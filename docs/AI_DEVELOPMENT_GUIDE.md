# AI 开发工作规范

> 本项目以 AI 完成编码与文档工作。人负责需求、授权、账号操作、真机操作及最终取舍；AI 负责提出方案、实现、测试与提供证据。
> 本文为工作规范，不代表已有实战统计。旧版的胜任度星级、95% 成功率与虚构案例已撤下。
> 维护者：xyyi0719

## 1. 不变规则

1. **先查仓库事实**：区分实现、计划、建议和未知。文档存在不等于功能存在。
2. **小步闭环**：一次只实现一条可验收链路，避免同时生成多个未验证 crate。
3. **先列反例**：测试预期来自协议/需求，不来自实现本身。生成代码与生成测试可能共享同一错误假设。
4. **不编造结果**：命令未运行写“未运行”；0 tests 不写“业务测试通过”；mock 通过不写“真实邮箱可用”。
5. **核对依赖 API**：以锁文件、已安装源码和对应版本官方文档为准；新版本不是天然更适合。
6. **安全不降级**：不把授权码发到对话或 Git；不因 TLS/钥匙串失败而跳过校验或明文保存。
7. **范围受控**：Gmail 暂缓；不自行取消 Android，也不擅自引入服务器或改变用户已确认的同步层次。
8. **可追溯交付**：列出改动、验证命令/结果、未覆盖场景、风险与下一步。

## 2. 人与 AI 的职责边界

| 工作 | AI 负责 | 需要人的动作 |
|---|---|---|
| 架构与协议 | 查证、比较备选、列反例、写 ADR 草案 | 确认影响范围/风险取舍 |
| 编码与测试 | 实现、故障注入、修复与说明 | 必要时提供环境，不要求手写代码 |
| 真实邮箱接入 | 编写只读 probe、脱敏日志、分析结果 | 本地配置凭据、批准破坏性操作 |
| 平台能力 | 写插件、测试步骤、解释限制 | 真机权限操作与观察 |
| 安全敏感逻辑 | 使用成熟库、最小设计、可重复测试 | 接受剩余风险；需要时寻求独立审查 |

“全部用 AI 开发”不等于“无人授权即可访问邮箱”，也不等于平台代码必须人工编写。
没有用户授权不启动子代理；独立复核可用新的审查轮次，不把同一模型自评当成安全认证。

## 3. 单任务流程

0. **若任务涉及脚本、CI、命令、网络或平台差异，先读 [ENVIRONMENT.md](ENVIRONMENT.md)。**
   该文档记录本机 shell / 代理 / DNS / 工具链限制与各平台 WebView 差异，
   是避免重复踩坑的权威来源。
1. 读取相关代码、架构、风险条目及测试规范。
2. 输出事实/未知、范围、验收标准与计划修改文件。
3. 提出成功/失败/边界测试，确认需要的外部授权。
4. 实现最小方案；只引入当前链路必需的抽象与依赖。
5. 运行受影响测试及静态检查；失败时保留证据，不绕过门槛。
6. 核查数据丢失、重复发送、凭据泄漏、无界队列/内存与取消行为。
7. 更新相关文档；交付实际结果与未验证项。没有测量样本不提供 AI 耗时倍率。

## 4. 可复用任务模板

### 4.1 实现功能

```text
目标：<一条用户/系统可观察行为>
当前事实：<现有模块、版本、接口>
范围：<允许改的文件/模块>
不做：<其他服务商/平台/抽象>
约束：遵循 ARCHITECTURE、SECURITY、TESTING_STRATEGY。
验收：<输入→输出；失败与恢复；数据不变量>
先给测试反例，再实现；API 不确定时先核实。
交付：修改文件、真实验证命令与结果、未验证项。
不要读取/打印真实凭据，不做未经授权的发信或删除。
```

### 4.2 只读协议探测

```text
目标：验证指定服务商的 TLS、认证、认证后 CAPABILITY、只读邮箱摘要。
凭据：用户在本机安全配置，不写入源码、日志、命令行参数或对话。
约束：连接/命令超时、TLS 校验、响应上限、脱敏；使用 EXAMINE 与 BODY.PEEK。
禁止：STORE、MOVE、DELETE、EXPUNGE、SMTP 发信。
输出：可重复命令、版本、能力集、失败阶段与脱敏记录模板。
无法连接时保留未知，不能判定协议不支持。
```

### 4.3 存储迁移

```text
目标：<表/索引/约束及不变量>
先读：已有迁移与 DAO；不要重复添加 UIDVALIDITY 同义字段。
要求：新库与旧库升级测试；外键删除策略逐条说明，不能一律 CASCADE。
FTS 必测：正文晚到、更新、删除、回滚、重建。
输出：迁移、DAO/事务边界、测试和实际运行结果。
```

### 4.4 架构复核

```text
只审查不修改代码。
按 数据正确性/安全边界/外部接入/运行平台/工程验证/范围治理 分类。
每个发现：证据位置、反例、影响、最小修正、验证方式。
区分已存在 bug、尚未实现、外部未知和可选优化；不凑问题数量。
改变已确认范围的建议必须标为待决策，不能写成已接受 ADR。
```

## 5. 常见错误与正确检查方式

### 5.0 环境类（先查 ENVIRONMENT.md）

- **Shell 假设**：Windows 默认是 PowerShell，不支持 `$(...)`、`grep`、`2>/dev/null`。
  写 CI 步骤时显式声明 `shell: bash`，或改用跨平台写法。
- **多层引号**：命令会被外层 shell 再解释一次。`curl -w "%{http_code}"` 的 `%{` 可能被展开；
  复杂逻辑改用脚本文件而非单行命令。
- **网络**：本机 `github.com` 被 DNS 劫持到 127.0.0.1、SSH 22 端口被拒；
  `gh` 会自动读系统代理，`git`/`curl` 不会。需要时用 `api.github.com`、SSH over 443 或 `--resolve`。
- **注释里的文档路径**：相对源文件目录算层级，`crates/xremail-core/src/` 是 3 层，`apps/shell/src-tauri/src/` 是 4 层。
- **平台差异**：Windows/Android 是 Chromium 系，Linux/macOS 是 WebKit 系；
  沙箱 iframe、CSP、`srcdoc` 的行为不能跨引擎推断。

### 5.1 代码类

- **并发**：短临界区且不跨 await，`std::sync::Mutex` 可能合适；需要异步等待或持锁跨 await 时评估异步锁，优先避免持锁跨网络等待。两个加锁自增本身不是数据竞争；未等待任务完成是生命周期问题。
- **异步**：不是所有 future 都必须立刻 await（可能 spawn/join/返回）；必须证明任务被监督、错误被观察、退出可取消。
- **资源**：Rust RAII 释放句柄不代表协议完成；检查退出、超时、取消与服务器已执行但应答丢失的窗口。
- **IMAP**：Message-ID 不唯一且可缺失；UID 只在文件夹/UIDVALIDITY 内有效；HLC 无法补出服务器未提供的修改时间。
- **SQL/FTS**：不要根据看似合理的示例生成迁移；用真实 SQLite 执行并验证重建一致性。
- **HTML**：清洗后的字符串断言只是第一层；必须验证实际 WebView 中没有网络泄漏和宿主权限越界。
- **依赖**：TOML 中 `"1.28"` 是兼容版本范围，不等于精确固定在 1.28；可复现版本看 lockfile。
- **文档**：不虚构基准、案例、日期、完成状态、审核周期或支持平台；旧文档冲突要显式注明替代关系。
